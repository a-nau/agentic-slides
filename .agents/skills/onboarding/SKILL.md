# Onboarding to agentic-slides

Get a newcomer from clone to "my deck is on screen" in a few minutes, then show
where the deeper features live. Do the steps for them where you can; explain
in one or two lines each, not a lecture.

## The mental model (say this first)

- A **deck** is one Markdown file: `decks/<category>/<name>/slides.qmd`
  (Marp-style markdown rendered by [Quarto](https://quarto.org)/reveal.js, the
  `agentic` theme). Figures sit next to it in `images/`.
- A **live server** renders every deck and re-renders it on save.
- **Agents do the heavy lifting**: the skills in `.agents/skills/` build decks
  (`slide-deck`), review them (`deck-feedback`), and export them
  (`export-all-html`).
- **Publishing** is `git push`: GitHub Pages renders every deck.

## 1. Setup (once)

Needs Python 3, npm (once, for the local MathJax) and Google Chrome (PDF /
editable-PPTX exports).

```bash
scripts/setup.sh     # .venv (server, comments, exports), Quarto + MathJax into quarto/, git hooks
```

Report anything that failed and what that disables; don't install system
packages for the user.

## 2. Start the server

```bash
scripts/start.sh     # http://localhost:8093 — index of all decks (API on :8094)
scripts/stop.sh
```

Check it is up (`curl -fs localhost:8093/healthz >/dev/null`) before giving the URL,
and give the login URL `scripts/start.sh` printed (it ends in `?token=…`; the
token is in `.quarto/server-token`). Opening it once sets a cookie.
The server listens on 127.0.0.1 only. If the user browses from another machine
(LAN, VPN, laptop → workstation), start with `SLIDES_HOST=0.0.0.0 scripts/start.sh`
and give the host's reachable name, not `localhost`.

## 3. First deck

Pick one:

- **Look at the example** — `decks/templates/visual-gallery/` shows hover maps,
  timelines, charts, and animated mechanisms, all generated by `make_figures.py`;
  open `http://localhost:8093/templates/visual-gallery/slides.md`.
- **Scaffold** — `scripts/new_deck.sh tools/my-topic "My Topic"`, then edit
  `slides.qmd`; the open page updates on save.
- **Ask the agent** — e.g. *"make a deck introducing the repo at ~/code/foo"*;
  this runs the `slide-deck` skill (deck types: repo intro, MR review, tool
  demo, literature overview, paper deep dive).

Categories: `tools`, `repos`, `reading-groups`, `paper-reviews`,
`investigations`, `templates`, `mrs`.

## 4. Iterate

- **Comment**: select text on a slide → 💬 Comment. Saved to
  `decks/<…>/comments.json`; ask the agent to "address the open comments" (`address-feedback` skill).
- **Edit in the browser**: the **Edit** button in the bottom hover bar.
- **Fresh-eyes review**: ask for the `deck-feedback` round.

Comments and edit mode need the running server from step 2.

## 5. Export and publish

```bash
scripts/export.sh templates/visual-gallery pdf   # also: pptx (editable), html
```

Pages: push to `main` (after the one-time **Settings → Pages → Source: GitHub
Actions**). The site is read-only — no downloads unless the workflow is run
by hand with **exports** ticked (then its buttons serve prebuilt
HTML/PPTX/PDF); comments and edit mode stay local.
